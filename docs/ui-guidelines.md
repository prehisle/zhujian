> 来源:2026-07-17 UI 交互与可用性审计(桌面端 + 安卓端,27 条)的系统化蒸馏。
> 用途:① 修 P2/P3 时的对照表;② P0/P1 修完后喂给 Claude Design 建设计系统的核心输入;③ 新功能开发的默认约束。

## 一、设计原则

数据正确性工程(并发序号守卫、指纹防闪、两拍 token、space+seq 双复核)是本项目已达成的底线,不在本规范范围内。本规范补的是审计指出的系统性短板:**失败之后用户看到什么,误触之后怎么回头**。五条原则:

1. **布局稳定**:屏幕上任何元素不因反馈、确认、远端同步而移动。手指落下时和抬起时,屏幕必须一样。(审计 #3、#4、#13、#18)
2. **误触可逆**:每一个写操作要么有确认拍,要么有撤销窗口;破坏性越强,入口越难够到。(审计 #5、#11、#15)
3. **失败必见**:错误比成功更显眼、更持久;卡片级失败不牵连整版。(审计 #6、#22、#26)
4. **输入安全**:中文 IME 组合期永不触发提交;任何提交点有 in-flight 闸。(审计 #1、#2)
5. **触达与可见**:触屏目标够大,键盘焦点可见,搜到的必能跳到。(审计 #8、#10、#20)

## 二、Token 层(设计变量)

### 2.1 颜色与对比度

- 信息性文字对比度 ≥ 4.5:1(WCAG AA)。`--ink-faint`(≈2.5:1)仅限纯装饰元素(分隔符、水印类),禁止承载需要阅读的内容。【违例:9.5–11.5px 小字大面积用 --ink-faint,审计 #25】
- 危险色(朱砂/朱红)只出现在破坏性确认的**执行钮**上,不用于常驻入口。常驻的破坏性入口用低权重样式(ghost/次级)。【违例:回收站顶部通栏朱红「清空回收站」,审计 #23】
- 错误与成功不得仅靠颜色区分:错误必须叠加图标或「出错:」前缀。(审计 #22)
- CSS 变量必须有定义,禁止引用不存在的 token。【违例:board.css `var(--rule)` 未定义,应为 `--line-strong`,审计 #25 —— **336 才真修掉**,那之前看板的标签搜索框从来就没有边框(不带兜底的 `var()` 会让整条声明作废,静默)】
- **压在朱砂上的字走 `--on-seal`,不许写死白色**(336):暗色档的朱砂偏亮,白字只有 3.1:1。
- **hover / 按下一律往 `var(--ink)` 的方向压,不许往写死的 `#000` 压**(337)。「墨」按定义是纸的对极,亮色档深、暗色档浅,故同一句 `color-mix` 在两档里都表示「离纸面更远、更凸出」,**翻面由令牌自己完成**。用量:实心的朱砂主按钮 12%,幽灵按钮 6%(半透明水痕)。【违例:337 之前 6 处朱砂按钮写死 `#000`,暗色档下悬停是往回退,对 `--on-seal` 从 5.32 掉到 4.23】
- **状态规则只改一半时,记得另一半是谁给的**(337)。`.x:hover { background }` 的字来自 `.x`;而更隐蔽的是**特异性抢走**:通用的 `.btn:hover:not(:disabled)`(0,4,0)会压过 `.btn.go`(0,3,0)的 `color`。【违例:「合并」钮悬停时字掉回 `--ink`,亮色档墨黑压朱砂 2.51:1】
- **写死颜色要有人签字**(339)。有些颜色就该写死 —— 压在**照片**上的蒙版与其上的字(底不是纸面,两档都得是深底浅字)、扫码要的白底黑码。判据不是「不许写死」而是「每一处都在 `scripts/check-hardcoded-colors.mjs` 的登记表里有一行,写清楚它为什么不随明暗档翻面」。**同一个语义在两端各写一个值 = 漂移,必须收成令牌**(判例:同步状态点的「已连」绿有过三个抄写点,339 收进 `--ok`);两端本来就是不同表达的**不算**漂移(判例:「连接中」桌面是琥珀、安卓是朱砂淡,登记即可)。
- 以上由 `scripts/check-contrast.mjs`(前四条)与 `scripts/check-hardcoded-colors.mjs`(末条)守着,明暗两档逐组算、按元素层叠;**343 起前者还认字号**,§2.2 第二条那条「小 × 淡」的底线由它一并守着。**338 起两个 html 壳的内联 `<style>` 已在扫描面内**(那一轮就是靠它逮到 `--surface` 幽灵令牌与 `.wc-close:hover` 的白字);今天剩下的盲区是祖先背景 / 半透明 / 伪元素 / 非后代组合子,每次跑都会印出条数。

### 2.2 字号阶(全局令牌,三份统一)

> **342 起这张表是被门禁核对的断言,不再是描述。** 值格的形状固定为 `` `--令牌` `` = 值;`scripts/check-fs-drift.mjs` 拿它与**三份令牌表**(桌面 `src/theme.css` / 安卓与官网各内联一份)对账,并照 341 的形多核一层**用法**:CSS 里的字号不许再出现尺寸字面量,每一处要么走令牌、要么在门禁的登记表里有一行。**改这张表 = 改代码,反之亦然。**
>
> 立这道闸的由来:字号此前**一个令牌都没有**,三份里散着 **29 种取值**,其中 12.5 / 11.5 / 14.5 / 10.5 / 9.5 / 16.5 / 13.5px 这类**半像素占 63 处** —— 没有任何判据能说清 12 与 12.5 的分别,它们只是历次微调的沉积。

| 令牌 | 值 | 用途 |
|---|---|---|
| `--fs-12` | 12px | **信息性文字的底线**(见下)。时间戳、计数、meta 行、标签 chip、次级提示 |
| `--fs-13` | 13px | 次级正文:卡片副文、按钮、输入框、列表项 |
| `--fs-14` | 14px | 正文基准(主窗 `body` 即此档) |
| `--fs-15` | 15px | 略重的正文:侧栏导航、安卓 compose、官网导航 |
| `--fs-16` | 16px | 小标题:面板标题、搜索框、官网正文段 |
| `--fs-17` | 17px | 视图/空态标题、安卓 header |
| `--fs-18` | 18px | 官网引导段与纸片正文 |
| `--fs-20` | 20px | 桌面视图大标题、官网 pillar 标题 |
| `--fs-24` | 24px | 官网字标与落款 |
| `--fs-30` | 30px | 大字形按钮:看大图翻页箭头、安卓捕获 FAB |

**取哪一档 = 最近档取胜,等距时上取整**(照 §2.5 的判据;上取整是因为这一格的约束方向是「别更小」)。342 收敛 281 处声明、其中 101 处真动了像素,**其中 64 处只动 0.5px**(销半像素),≥1px 的仅 37 处。

**⭐ 最小档 12px 就是本节第一条规范,不是凑出来的**:

- **信息性文字最小 12px。阶下无档** —— 任何小于 12px 的字号必须在门禁的登记表里逐处签字说明「它是纯装饰」。判据是**「要读的」还是「要看的」**:词、数字、时间戳、键名都是要读的;`▸▾ × ✓` 这类字形当图标、只承载 `<svg>` 的按钮、`::before` 的记号是要看的。342 按这条判了 63 处,50 处抬到 12px、12 处签字留下。
- 立这条闸当天逮到的原型:`.color-swatch.none` 在一枚 17px 圆钮里用 `--ink-faint` 写 **9px 的「无」**——正是 §2.1 那句「9.5–11.5px 小字大面积用 `--ink-faint`,审计 #25」,而它**藏在 `font: 9px/1 …` 简写里**,只扫 `font-size` 的盘点整个看不见它。

**不在阶上的**(门禁的登记表里逐处有一行,两个方向都核):官网三处 `clamp()` 流体标题(随视口流动,不是阶上的一档)与 `.img-ref` 的 `0.86em`(相对宿主缩一档,宿主可能是 13px 的时间轴行也可能是 14px 的正文 —— 与 341 那条 `border-radius: inherit` 同型)。

**诚实边界**:

- 这道闸只核**值**,不核「谁该用哪一档」——档名是提示不是契约(同 §2.5)。
- 小于 14px 的文字禁止与低对比色叠加(小 × 淡 = 不可读)。(审计 #25)**343 起这一条是断言**:`scripts/check-contrast.mjs` 认字号了 —— 每个元素签名的生效字号照它那套迷你层叠算出,**小于 14px 的一档底线从 4.5:1 抬到 5.0:1**,低于它且没登记即拒。
  - **5.0 这个数是量出来的**:坎在 5.32 —— 朱砂主按钮那对色(`--on-seal` 压 `--seal`)就是 5.32(336 用户拍板),它铺在三端所有主按钮上。底线取 5.5 会让 40 组红、其中 31 组是那颗按钮;取 7.0(WCAG AAA)则是 60 组、等于重挑品牌主色。**一道要靠二十几条例外才过得去的闸已经在说假话**,故可取区间是 (4.5, 5.32],取整数档 5.0(用户 2026-08-08 在代价表上拍板)。⚠ 它不是「AAA 那种有出处的数」,是本设计系统里**能与既有主色共存的最高一档**;朱砂那对色哪天改了,这个数要重算。
  - 两条出路是对称的:**别那么小**(抬到 14px)或**别那么淡**(换配色),门禁的红字里两条都写着。343 当天两处真判例各走一条 —— 安卓通知条 13→14px(墨绿底压 `--on-seal` 只有 4.79),标签详情复制钮的 hover 由朱砂换回 `--ink`(12px 上朱砂压抬升纸面暗档只有 4.87)。
  - ⚠ **诚实边界:字号是继承来的,而那套层叠只在同一个元素身上做。** 自己那条链上没人写 `font-size` 的签名定不出多大,一律按 4.5 判并单独计数印出来(今天 158 组里 16 组)。这个方向是 fail-open 的 —— 猜「继承自 body」会在小容器里判漏(安静的绿),猜「就是小字」会误报,两条都比不判更糟。
- 字号只是可读性的一半,另一半是**行高与字距**,两者今天都不在任何闸的扫描面内。

### 2.3 触区与间距

- **安卓**:所有可点元素触区 ≥ 44×44px。视觉尺寸可以保持小巧,用 `padding` 或 `::before` 扩触区。`.tick` 勾选区拓到 48px。【违例:.ghost ≈27px、面板主操作 ≈31px、pill ≈25px、.space-row .act ≈24px、底栏 ≈29px,审计 #10】
- **桌面**:鼠标热区 ≥ 24×24px(WCAG 2.2 目标尺寸底线)。**356 起这条是被门禁核对的断言**(`scripts/check-hit-zone.mjs`):枚举面 = 桌面两文档层叠后 `cursor:pointer` 的全部签名(不手写控件清单,新按钮写了 cursor 即自动进面),判据 = **「自身声明能否保证 ≥24」**而非估算真实尺寸(显式尺寸 / 行盒下界 fs×lh+padding+border / 热区扩展 ::before,扩展宿主必须已定位);给不出保证的必须在闸内 REGISTRY 登记签字(WCAG 2.5.8 的 spacing/inline 豁免只能人判)。【审计 #25 三违例已 354 修(视觉不动,::before 撑 24×24);356 建闸并修 .mb-chip-x / .cm-close,**闸首跑即抓出 354 的 .img-del 扩展漏了捕获窗**(controls.css 只被主窗加载,扩展已搬家 item-images.css);**357 存量清账:19 处扩展 + 登记定稿 10 条,枚举面上违例清零、热区三轮全案终了**——Chrome 实测又逮出「**自剪裁死扩展**」一族(.mb-chip-label/#cap-space 自带 overflow:hidden,::before 被宿主自己裁掉,闸已升级静态判此形);.tag-x 9px 字形与色板格 17×17 用户 2026-08-09 拍板不动观感,登记在案】
- 破坏性单拍控件与任何两拍确认的第二拍之间,间距 ≥ 8px 或分行,禁止毗邻。【违例:回收站「恢复」毗邻「确认彻底删除」,审计 #4】
- **间距有意不建阶、不设 4px 栅格(344 拍板,别再当悬案翻出来)**:量出来的分布是 43 种取值、1–16px 每个整数都有人用、875 个 px 值里栅格外的占 445 —— 与圆角(17 种收 4 档)/字号(29 种收 10 档)不同,间距的值空间实际上是连续的,没有潜在的阶可「恢复」,强收 = 一次全站布局重设计,且那道闸要靠几百行登记才过得去(§2.2 的纪律:那样的闸在说假话)。间距的真病是**跨文件的派生约束抄写点漂移**(视图头「右侧躲开 3×46=138px 窗控」那笔账此前只存在于三处复制的注释里),照 §2.4 时长常量的形收成令牌 `--wc-w` / `--winctl-dead`(桌面份,见 theme.css 与 check-theme-drift 登记表);微调间距(padding/margin/gap 的字面量)诚实地不在任何闸的扫描面内,与行高/字距同格。判据分析与代价表见 progress-log 344。

### 2.5 圆角阶(全局令牌,三份统一)

| `--radius-circle` | 50% | 正圆(**只对正方形元素成立**):同步状态点、色板格、圆形删除钮 |
| `--radius-seal` | 25% | 朱砂小方块那枚记号:半径 = 边长的 1/4,**随尺寸走**。它在三份里有 12 / 9 / 8px 三个尺寸,写成百分比之后「同一枚记号」才是结构事实而不是三处巧合(同样只对正方形成立) |

**取哪一档 = 最近档取胜**,不按语义硬套:档名是提示不是契约。341 收敛 190 处声明、其中 82 处真动了像素,**每一处位移都 ≤2px** 就是这么定的;硬按语义套会让「小别名输入」这种从 4px 跳到 8px,那是没人要求的观感改动。

**不在阶上的**(门禁的登记表里逐处有一行,两个方向都核):`0`(某个角明确不圆,如底部弹层的 `var(--radius-lg) var(--radius-lg) 0 0`)与 `inherit`(描边追随宿主,宿主是谁都对)。

**诚实边界**:这道闸只核 `border-radius` 这一个属性的**值**,不核「谁该用哪一档」;也不核 `overflow: hidden` 有没有跟上(圆角容器里的图不裁是另一类 bug,今天没有任何门禁看得见)。

## 三、组件模式层

### 3.1 Toast / 提示条

- 一律 `position:fixed` 悬浮,**永不占文档流**——这是安卓端最大误触源的根治。【违例:#error、#update 均在文档流内,出现/消失让时间轴跳 ~37px,审计 #3】
- 三种形态:
  - **成功型**:按字数读秒自动退(见 §2.4 `TOAST_SUCCESS`),点按可提前收;
  - **操作型**:成功型 + 撤销按钮,如「已完成 · 撤销」(完成/删除/归档等可逆离场动作必须配发)(审计 #15);
  - **错误型**:6s 自动退 + 点按关闭、带图标或「出错:」前缀、原始错误码前加人话(审计 #22、#26)。
- **一律可点按关闭**(222):自动退场是兜底不是唯一出路,用户读完了就该能立刻收掉。
- **两端各有一条通用回执通道,别再各写各的**(228):桌面 `src/toast.ts::toastAction`(底部中央,2.2s),安卓 `ui.ts::showBar(msg, true)`(顶部条,按字数读秒)。**动作做完必须说话**——「跨空间移动成功」原先桌面静默、安卓给绿条,就是漏了这条导致的端间分叉。
- 更新提示(#update)同样悬浮,不推挤 header 下方内容。(审计 #3)

### 3.2 破坏性确认流(两拍)

确认态的完整契约,六条缺一不可:

1. **固定几何**:确认态不改变按钮宽高、不引发换行——`min-width` 预留或独立确认行。【违例:「删除」→「确认删除?进回收站」变宽致 flex-wrap 换行,审计 #4】
2. **落点错开或 300ms disabled,二选一**:执行钮不得出现在触发钮的原落点上(执行放左、取消放右),**或**执行钮出现后 300ms 内 disabled 防连击——这是审计 P0 #5 修法的原文,桌面走前者(`inbox.ts` trashBar)。⚠ 本条曾被抄成「并叠加」,在 §2.4 挂账约五周;2026-08-08 用户拍板「或」是原意,改回并销账(过程见 progress-log 340 §四、344 续)。【违例:清空回收站执行钮与原按钮右缘对齐,双击即全清,审计 #5】
3. **Esc 逃生**:确认态复用 armDismiss,Esc / 点外即取消——全应用交互中唯独确认流没有逃生键是不可接受的。(审计 #12)
4. **3s 自动复原** + token 防重放(现状已有,保持)。(审计 #4)
5. **周边无雷**:确认态出现时,毗邻控件不得是单拍即写的(状态 pill、恢复钮等)。(审计 #4)
6. **权重升格**:数据后果越重,确认钮越大——空间重置这类删全部数据的确认按钮应全宽、与取消拉开距离。(审计 #11)

### 3.3 提交型输入(所有 Enter 提交点)

- 第一行永远是 `if (e.isComposing) return`——中文 IME 组合期的 Enter 是选词,不是提交。适用:捕获浮窗、灵感「记下」、看板新建、行内编辑、topics 表单、安卓 compose。【违例:全仓无一处 isComposing,审计 #1】
- 每个提交点配 in-flight 闸(照抄 openEdit 的 `saving` 模式):提交中忽略再次触发,防 IPC 往返窗口内双 Enter 重复入库。【违例:main.ts 捕获 / inbox.ts save / board.ts submitNewTask,审计 #2】
- 成功后的反馈契约:清空输入框;**安卓额外 blur 收键盘** + 新卡 `.flash` 高亮入场(连记场景给「继续记」显式入口,而不是永不收键盘)。【违例:save() finally 无条件 ta.focus(),审计 #7】

### 3.4 错误呈现分级

- **卡片级失败**(单卡的 archive/seal/标签/恢复失败):就地显示在该卡上(inbox 编辑态已是此模式,推广之),其余内容不动。
- **整版错误页**(renderError):只保留给列表**初次读取**失败,且必须带「重试」按钮。
- 禁止:小操作失败把整个看板/列表连 compose 一起替换掉。【违例:board.ts call() / tasktime.ts / inbox.ts doArchive 等全走 renderError,审计 #6】
- 任何写操作失败必须有可见反馈——删图失败无反应、取图列表失败显示为「无图」这类静默失败不允许。(审计 #26)

### 3.5 焦点与键盘

- 所有 hover 显形的控件必须同时 `:focus-visible` 显形(补 `opacity:1; outline`),容器配 `:focus-within`。【违例:.hk-btn、标签行操作、.dtask-copy 键盘焦点不可见;全仓无 :focus-visible,审计 #20】
- **hover 显形的容器一旦就地展开「要交互的东西」(输入框 / 调色板 / 两拍确认 / 失败提示),必须钉住可见、不再依赖悬停。** 否则鼠标一离开那一行它整块隐形,而键盘焦点还在输入框里(看不见的输入框);报错更是当场变成**静默失败**,与 §3.4 末条直接打架。判据 = 进入非默认态时加一个显式状态类,**且那一档不许淡入**(淡入期间 opacity 真的有一瞬等于 0——这同时是 e2e `waitForDisplayed` 判不可见的判据)。【377 修:标签行 `.topic-actions`;同形别处未扫,见 progress-log 377 可优化项】
- 模态面板(同步面板等):`role="dialog"`、打开即聚焦首个控件、Tab 圈闭在面板内不走到遮罩后。(审计 #21)
- 安卓返回键账本分层,popstate 优先级:**scan > ritual > viewer > pane**——扫码与恢复码仪式必须各压一层,防返回键旁路「输对才放行」契约。(审计 #16)

### 3.6 布局稳定与滚动

- 面板开关保存/恢复滚动位:openPane 记 scrollY,closePaneNow 后恢复。【违例:pane-open 令 #timeline display:none,scrollTop 钳到 0,审计 #13】
- 远端新条目顶部插入时:用户不在顶部则补偿 scrollY,或显示「有新记录 ↑」胶囊代替直接重排。(审计 #18)
- (与 3.1 同源)任何反馈/确认元素不得改变文档流几何。
- **手势即回执(乐观呈现)**:拖放/按键等写手势结束的那一帧,DOM 就呈现手势的结果(乐观移位/离场);后端真相回来只做校正,失败由重载复原。禁止「先弹回旧态、真相到了再跳到新态」。旁路复核:在途未落账(busy)时整个手势不接——连乐观移位也不做,不留无人持久化的假象。(2026-07-19 拖拽弹回案:board.ts drop/归档区/键盘移列)
- **全量重画必须保留滚动位**:重画定局处记录、落 DOM 后还原(灵感 savedScroll / 看板 colScroll 同规);指纹短路(§六-4)挡住的是"没变不画",这条兜的是"真画了不丢现场"。(2026-07-19 同案)
- **定制滚动条要把四个部件一起定**(249):只要有任一 `::-webkit-scrollbar*` 规则命中,整条滚动条改走自绘,**没写到的部件退回浏览器默认的白**——轨道白一层(被 thumb 的纸边遮掉大半、平时看不出),横竖同现时右下角那枚 `-corner` 就露成一块白方块。定 `width` 就顺手定 `height`(否则横条比竖条粗一圈)、定 `-thumb` 就顺手定 `-track` / `-corner`(铺 `transparent` 让元素底色透上来,深浅色都自洽)。
- **卡片里的 `nowrap` 元素必须能缩**(249):标签 chip / 日期 chip 这类 `white-space:nowrap` 的东西,一枚长内容就能把卡片撑破、逼出意外的横向滚动条(纵向 `overflow-y:auto` 会把横向一并从 `visible` 提成 `auto`)。做法=文字包一层做 `text-overflow:ellipsis`,操作按钮 `flex:none` 不缩(窄卡上先消失的不该是操作)。**别用 `max-width:100%` 封顶**:若包含块自己是 shrink-to-fit(inline-flex 的 slot 层),百分比循环引用会被浏览器直接忽略——要靠**每一层** flex item 都 `min-width:0`。验收得**量**(`getBoundingClientRect` 逐层 + `scrollWidth == clientWidth`),光看截图分不清"缩了"还是"恰好没溢出"。(2026-07-29 看板长标签案;灵感 `.tag-label` / 搜索 `.chip` 是同一手法的既有先例)
- **判定窗口不是白等,得立刻起过渡**(246):为等双击/长按判定而**故意挂起**的动作(看大图轻点关就是),挂起那段必须**在按下的那一帧就开始可见的过渡**(淡出/位移),第二击到了再把过渡平滑撤销。用户读成「卡」的是**点了没反应**,不是「没立刻完成」——所以别去砍判定窗口换手感,那是拿双击容错换的:安卓真机实测,窗口砍到 200ms 后间隔 226ms 的双击第一击就把图关了(系统标准 300ms/Android、500ms/Windows,砍到标准以下必出这种失手)。**验收要点**:光断言 class 挂上了不够,得量中途 `getComputedStyle().opacity` 落在 (0,1) —— 否则选择器写错、过渡根本没跑,断言照样绿。(2026-07-29 看大图关闭案:桌面 `.img-lightbox.closing` 只淡内容[黑底要留着盖住缩窗]、安卓 `#viewer.closing` 整层淡)

### 3.7 加载与刷新

- 任何可感知延迟(> 100ms 量级)的 await 即时给加载态:点缩略图**先开查看器显加载态**,字节到了再换 src。加载指示延迟 ~200ms 淡入——快路径(缓存命中/小图)不给一闪而过的 loading。(审计 #14)
- **布局未定不显示**:最终几何要靠多步异步(取字节/量窗口/放大窗口)才定形的元素,定形前保持不可见(出生即隐形零占位),定形后一次成形亮相;禁止裸渲染中间态——「图先以原始尺寸闪现、窗口再放大反排、最后猛缩到位」就是这条的反例。(2026-07-19 看图闪烁案:makeImageViewer)
- 时间轴提供下拉刷新兜底(触发 refresh + 一次追赶),不把唯一恢复手段藏在空间面板深处。(审计 #17)

### 3.8 危险操作入口权重(三级)

| 级别 | 定义 | 入口规格 | 例 |
|---|---|---|---|
| 高频安全 | 日常写操作 | 主按钮、大触区、拇指区 | 记下、完成勾选、搜索(搜索当前 12px 且在拇指区外,应升权,审计 #23) |
| 低频破坏 | 可恢复的删除类 | 次级样式 + 两拍 | 删除进回收站、归档 |
| 重破坏 | 不可恢复/删全部 | **收进详情页或长按菜单,不常驻列表行**;确认钮全宽 | 空间重置(审计 #11)、清空回收站(审计 #23) |

### 3.9 导航连通性

- 凡搜索能搜到的对象,必能一键跳转定位:按 status 分流——task → 看板/时间轴定位,灵感 → 灵感视图定位,回收站/归档 → 对应面。两端跳转基建都现成(桌面 focusTask、安卓 focusTimelineCard)。【违例:两端搜索结果均不可点,审计 #8】

## 六、工程约定(不进设计系统,进 repo 的开发规范)

这些是审计 #9 一族的根因约定,设计系统管不到,但必须成文:

1. **状态归属**:编辑态、草稿、暂存图一律在模块态(state),禁止只活在 DOM 里——切视图/切空间/远端刷新都不应丢。(审计 #9d)
2. **监听回收**:每个 mount 文档级监听的视图必须提供 unmount 清理钩子;残留监听对旧 id 发 commit 是数据事故。(审计 #9a)
3. **刷新前保护**:load() 发现 sig 变化时,先 commit 或回灌进行中的编辑再重绘(inbox 与 board 行为必须一致)。(审计 #9b)
4. **指纹短路**:所有全量重绘入口配 lastSig,内容未变不重绘(topics 补齐)。(审计 #9c)
5. **竞态守卫在 await 之前**:菜单双开类守卫必须在异步调用前置位。(审计 #21)
6. **昂贵查询缓存**:list_item_images 之类按会话缓存,重渲不重查(审计 #19)。不可变数据(图字节:只增删不改)按 id 缓存**成功结果**、永不失效,删除时清项只是内存卫生;⚠️ 只缓存已到手的值,不缓存 Promise——统一 invoke 包装把跨空间迟到响应变成「永不决议」(space.ts stale),缓存 Promise 会把这种挂起永久钉进 Map。(2026-07-19,item-images.ts srcCache)
