## 一、设计原则

数据正确性工程(并发序号守卫、指纹防闪、两拍 token、space+seq 双复核)是本项目已达成的底线,不在本规范范围内。本规范补的是审计指出的系统性短板:**失败之后用户看到什么,误触之后怎么回头**。五条原则:

1. **布局稳定**:屏幕上任何元素不因反馈、确认、远端同步而移动。手指落下时和抬起时,屏幕必须一样。(审计 #3、#4、#13、#18)
2. **误触可逆**:每一个写操作要么有确认拍,要么有撤销窗口;破坏性越强,入口越难够到。(审计 #5、#11、#15)
3. **失败必见**:错误比成功更显眼、更持久;卡片级失败不牵连整版。(审计 #6、#22、#26)
4. **输入安全**:中文 IME 组合期永不触发提交;任何提交点有 in-flight 闸。(审计 #1、#2)
5. **触达与可见**:触屏目标够大,键盘焦点可见,搜到的必能跳到。(审计 #8、#10、#20)

## 二、Token 层(设计变量)

### 2.1 颜色与对比度

- 信息性文字对比度 ≥ 4.5:1(WCAG AA)。`--ink-faint`(≈2.5:1)仅限纯装饰元素(分隔符、水印类),禁止承载需要阅读的内容。【违例:9.5–11.5px 小字大面积用 --ink-faint,审计 #25】
  - ⚠ **这一条是意图,不是可执行的判据 —— 别拿它去立案**(620 栽过):343 **明确否掉过**「小字前景不许用 `--ink-soft` / `--ink-faint`」这种按令牌名下禁令的形(要维护一张「哪些令牌算淡」的名单而名单本身没人核,且会削掉刻意的视觉层次)。**能执行的是 §2.2 那条数值底线(<14px ≥ 5.0:1)**;单处该不该升档,判例是 336 的「那句话是这个区的**全部说明**,轻到读不出来就不是提示了」。存量清单在 [ui-consistency-plan](ui-consistency-plan.md) A 条(⚠ 内部文档,公开仓没有)。
- 危险色(朱砂/朱红)只出现在破坏性确认的**执行钮**上,不用于常驻入口。常驻的破坏性入口用低权重样式(ghost/次级)。【违例:回收站顶部通栏朱红「清空回收站」,审计 #23】
- 错误与成功不得仅靠颜色区分:错误必须叠加图标或「出错:」前缀。(审计 #22)
- CSS 变量必须有定义,禁止引用不存在的 token。【违例:board.css `var(--rule)` 未定义,应为 `--line-strong`,审计 #25 —— **336 才真修掉**,那之前看板的标签搜索框从来就没有边框(不带兜底的 `var()` 会让整条声明作废,静默)】
- **压在朱砂上的字走 `--on-seal`,不许写死白色**(336):暗色档的朱砂偏亮,白字只有 3.1:1。
- **说明 / 计数类小字走 `--ink-soft`,不用 `--ink-faint`**(908 桌面收了十一处;`--ink-faint` 只留给纯装饰)。
- **朱砂当小字、自己不带底直接压在纸面(纸底 / 卡片 / 面板)上,走 `--seal-ink`,不走 `--seal`**(用户面 132):`--seal` 压这几层底够不上 §2.2 小字 5.0(亮压纸底 4.93、渐变底端 4.75;暗压卡片 4.87、底端 4.41)。`--seal` 留给按钮、描边、淡朱底与强调面。算法与读数见 `src/theme.css` 那段注释。自带淡朱底(`--seal-tint`,染色卡里是 `--seal-tint-solid`)的 chip / 选中态是另一对色,走 `--seal-ink-on-seal-tint`(用户面 133):亮档往 `--ink` 压到淡朱底叠三层纸面都 ≥ 5.0;⚠ 暗档那枚刻意等于暗档 `--seal`、仍不过(用户看对比图拍板,另一条路在 backlog 用户面 135)。
- **hover / 按下一律往 `var(--ink)` 的方向压,不许往写死的 `#000` 压**(337)。「墨」按定义是纸的对极,亮色档深、暗色档浅,故同一句 `color-mix` 在两档里都表示「离纸面更远、更凸出」,**翻面由令牌自己完成**。用量:实心的朱砂主按钮 12%,幽灵按钮 6%(半透明水痕)。【违例:337 之前 6 处朱砂按钮写死 `#000`,暗色档下悬停是往回退,对 `--on-seal` 从 5.32 掉到 4.23】
- **状态规则只改一半时,记得另一半是谁给的**(337)。`.x:hover { background }` 的字来自 `.x`;而更隐蔽的是**特异性抢走**:通用的 `.btn:hover:not(:disabled)`(0,4,0)会压过 `.btn.go`(0,3,0)的 `color`。【违例:「合并」钮悬停时字掉回 `--ink`,亮色档墨黑压朱砂 2.51:1】
- **写死颜色要有人签字**(339)。有些颜色就该写死 —— 压在**照片**上的蒙版与其上的字(底不是纸面,两档都得是深底浅字)、扫码要的白底黑码。判据不是「不许写死」而是「每一处都在 `scripts/check-hardcoded-colors.mjs` 的登记表里有一行,写清楚它为什么不随明暗档翻面」。**同一个语义在两端各写一个值 = 漂移,必须收成令牌**(判例:同步状态点的「已连」绿有过三个抄写点,339 收进 `--ok`);两端本来就是不同表达的**不算**漂移(判例:「连接中」桌面是琥珀、安卓是朱砂淡,登记即可)。
- 以上由 `scripts/check-contrast.mjs`(前四条)与 `scripts/check-hardcoded-colors.mjs`(末条)守着,明暗两档逐组算、按元素层叠;**343 起前者还认字号**,§2.2 第二条那条「小 × 淡」的底线由它一并守着。**338 起两个 html 壳的内联 `<style>` 已在扫描面内**(那一轮就是靠它逮到 `--surface` 幽灵令牌与 `.wc-close:hover` 的白字);今天剩下的盲区是祖先背景 / 半透明 / 伪元素 / 非后代组合子,每次跑都会印出条数。

### 2.2 字号阶(全局令牌,三份统一)

> **342 起这张表是被门禁核对的断言,不再是描述。** 值格的形状固定为 `` `--令牌` `` = 值;`scripts/check-fs-drift.mjs` 拿它与**三份令牌表**(桌面 `src/theme.css` / 安卓与官网各内联一份)对账,并照 341 的形多核一层**用法**:CSS 里的字号不许再出现尺寸字面量,每一处要么走令牌、要么在门禁的登记表里有一行。**改这张表 = 改代码,反之亦然。**
>
> 立这道闸的由来:字号此前**一个令牌都没有**,三份里散着 **29 种取值**,其中 12.5 / 11.5 / 14.5 / 10.5 / 9.5 / 16.5 / 13.5px 这类**半像素占 63 处** —— 没有任何判据能说清 12 与 12.5 的分别,它们只是历次微调的沉积。

| 令牌 | 值 | 用途 |
|---|---|---|
| `--fs-12` | 12px | **信息性文字的底线**(见下)。时间戳、计数、meta 行、标签 chip、次级提示 |
| `--fs-13` | 13px | 次级正文:卡片副文、按钮、输入框、列表项 |
| `--fs-14` | 14px | 正文基准(主窗 `body` 即此档) |
| `--fs-15` | 15px | 略重的正文:侧栏导航、安卓 compose、官网导航 |
| `--fs-16` | 16px | 小标题:面板标题、搜索框、官网正文段 |
| `--fs-17` | 17px | 视图/空态标题、安卓 header |
| `--fs-18` | 18px | 官网引导段与纸片正文 |
| `--fs-20` | 20px | 桌面视图大标题、官网 pillar 标题 |
| `--fs-24` | 24px | 官网字标与落款 |
| `--fs-30` | 30px | 大字形按钮:看大图翻页箭头、安卓捕获 FAB |

**取哪一档 = 最近档取胜,等距时上取整**(照 §2.5 的判据;上取整是因为这一格的约束方向是「别更小」)。342 收敛 281 处声明、其中 101 处真动了像素,**其中 64 处只动 0.5px**(销半像素),≥1px 的仅 37 处。

**⭐ 最小档 12px 就是本节第一条规范,不是凑出来的**:

- **信息性文字最小 12px。阶下无档** —— 任何小于 12px 的字号必须在门禁的登记表里逐处签字说明「它是纯装饰」。判据是**「要读的」还是「要看的」**:词、数字、时间戳、键名都是要读的;`▸▾ × ✓` 这类字形当图标、只承载 `<svg>` 的按钮、`::before` 的记号是要看的。342 按这条判了 63 处,50 处抬到 12px、12 处签字留下。
- 立这条闸当天逮到的原型:`.color-swatch.none` 在一枚 17px 圆钮里用 `--ink-faint` 写 **9px 的「无」**——正是 §2.1 那句「9.5–11.5px 小字大面积用 `--ink-faint`,审计 #25」,而它**藏在 `font: 9px/1 …` 简写里**,只扫 `font-size` 的盘点整个看不见它。

**不在阶上的**(门禁的登记表里逐处有一行,两个方向都核):官网那几处 `clamp()` 流体标题(随视口流动,不是阶上的一档)与 `.img-ref` 的 `0.86em`(相对宿主缩一档,宿主可能是 13px 的时间轴行也可能是 14px 的正文 —— 与 341 那条 `border-radius: inherit` 同型)。

**诚实边界**:

- 这道闸只核**值**,不核「谁该用哪一档」——档名是提示不是契约(同 §2.5)。
- 小于 14px 的文字禁止与低对比色叠加(小 × 淡 = 不可读)。(审计 #25)**343 起这一条是断言**:`scripts/check-contrast.mjs` 认字号了 —— 每个元素签名的生效字号照它那套迷你层叠算出,**小于 14px 的一档底线从 4.5:1 抬到 5.0:1**,低于它且没登记即拒。
  - **5.0 这个数是量出来的**:坎在 5.32 —— 朱砂主按钮那对色(`--on-seal` 压 `--seal`)就是 5.32(336 用户拍板),它铺在三端所有主按钮上。底线取 5.5 会让 40 组红、其中 31 组是那颗按钮;取 7.0(WCAG AAA)则是 60 组、等于重挑品牌主色。**一道要靠二十几条例外才过得去的闸已经在说假话**,故可取区间是 (4.5, 5.32],取整数档 5.0(用户 2026-08-08 在代价表上拍板)。⚠ 它不是「AAA 那种有出处的数」,是本设计系统里**能与既有主色共存的最高一档**;朱砂那对色哪天改了,这个数要重算。
  - 两条出路是对称的:**别那么小**(抬到 14px)或**别那么淡**(换配色),门禁的红字里两条都写着。343 当天两处真判例各走一条 —— 安卓通知条 13→14px(墨绿底压 `--on-seal` 只有 4.79),标签详情复制钮的 hover 由朱砂换回 `--ink`(12px 上朱砂压抬升纸面暗档只有 4.87)。
  - ⚠ **诚实边界:字号是继承来的,而那套层叠只在同一个元素身上做。** 自己那条链上没人写 `font-size` 的签名定不出多大,一律按 4.5 判并单独计数印出来(今天 158 组里 16 组)。这个方向是 fail-open 的 —— 猜「继承自 body」会在小容器里判漏(安静的绿),猜「就是小字」会误报,两条都比不判更糟。
- 字号只是可读性的一半,另一半是**行高与字距**,两者今天都不在任何闸的扫描面内。

### 2.3 触区与间距

- **安卓**:所有可点元素触区 ≥ 44×44px。视觉尺寸可以保持小巧,用 `padding` 或 `::before` 扩触区。`.tick` 勾选区拓到 48px。【违例:.ghost ≈27px、面板主操作 ≈31px、pill ≈25px、.space-row .act ≈24px、底栏 ≈29px,审计 #10;**514 补记标签面那一行**:`.tk-add` / `.tk-badge`(实测 **24**)/ `.tk-edit` 的两枚钮**今天都不到 44**(`.tname` 629 起已写死 44,`.thandle` 见下条判过不适用)—— **632 与 632 补两轮已销**(纵向:五枚小药丸并成一条 `::before` halo;横向:类型编辑态整行让位 + 那两处 gap 6→12);⛔ 这条清单**不是「除此之外都达标」**,它只是历次审计点过名的那几处】
- **两枚可点元素挨着时,横向的判据是「中心距 ≥44」,不是「各自宽 ≥44」**(632 补 实测立):原生触摸有一层吸附,手指落在两枚之间**会被吸到更近的那一枚** ⇒ 把 halo 往横向撑**一点也不改变边界在哪**,只有拉开中心距(把钮做宽、或把间距拉开)才真的多给出容错。⚠ 小钮扎堆时**先按中心距重算一遍再立案** —— 632 按「各自多宽」立的那条账,重算后发现三枚里两对本来就达标,立账写的那条风险(「点『存』会落到『删除』上」)根本不成立。⛔ 别把为这条定的 gap 当审美值往回调:旁边要写清它换来的中心距是多少。
- **给一行加东西之前先问「这一态该不该整行让位」**:标签面三个编辑态里,(当年)改名与改色都让位、类型编辑没让 ⇒ 六件东西挤在 360 宽里,真机实测溢出 9px,而**先被压没的恰恰是名字**(0 宽,正是本该留下的那一样)。⚠ 这种挤压**不报错、也不一定让页面横滚**,只有量 `scrollWidth - clientWidth` 才看得见。**159 起三态的分工**:改名整行让位(名字就在输入框里);改色时色板上头独占一行留着名字(W3 WM-31:整行换成色板会看不出在改哪个);类型编辑留名,框下多一行说明。
- **药丸类(有边框有底色的小 chip)只能用 halo 扩触区,⛔ 别照隐形盒那一形写 `min-height`**:`background:none;border:0` 的元素撑到 44 屏上看不出来,而可见药丸撑到 44 就是把 chip 变成大按钮 —— 632 那轮账里钉的修法正是这么错的。**halo 的 44 要写成「以宿主中心对称的定高盒」**(`top:50%; height:44px; translateY(-50%)`),⛔ 别写成「宿主高 + 上下各外扩 N」:那是**算出来的 44**,随界面字号四档漂(90% 档上够不到),而 `inset` 配 `min-height` 三者过约束、下缘时而生效时而被忽略,四档实测不成规律。
- **量 halo 只能真打点,且步长要细到亚像素**:`::before` 不进宿主的 `getBoundingClientRect()`(读 rect 恒红),读 `getComputedStyle(el,'::before')` 又退回「CSS 里写没写」;而**整像素步长的探针读数永远是整数、最多少报 1px**,一个真 44 会报 43 ⇒ 粗走跨界后二分细化。⚠ **原生触摸另有一层吸附**(Chromium touch adjustment):相邻两枚 halo 之间那几 px 的缝**不是死区**,手指落在缝里会被吸到更近的那一枚 ⇒ 「不该发生的那半」要判的是**会不会落到错的那一个**,不是「缝里点不中任何东西」。
- **拖动手柄不吃这条底线**(用户 2026-09-08 拍板;`.thandle` 实测 19.55×30)。⭐ **判据不是「拖比点容易」** —— 落手要落得准这件事上,手柄和按钮一样难;真正的分水岭是**落空的代价**。44 这条底线同时管两件事:①点得中 ②别点错。手柄这一族 **② 是结构上满足的**(`.thandle` 上下是 `.trow` 自己的 padding、再往外是别行的 padding,最近的可动元素在水平方向 30px 开外)⇒ 落空 = 什么都没发生、再来一次,**不会误触发别的动作**;① 确实是打了折的。⚠ **这是知情的取舍,不是达标** ⇒ ⛔ 别当漏检再报一次。⛔ **别把它外推成「非轻点手势一律免检」**:滑动删除、长按菜单那几族落空之后会真触发别的东西,② 不成立,底线照吃。**触发门**:哪天手柄的上下左右长出可动元素,这条当场作废。

### 3.2 破坏性确认流(两拍)

确认态的完整契约,七条缺一不可:

1. **固定几何**:确认态不改变按钮宽高、不引发换行——`min-width` 预留或独立确认行。【违例:「删除」→「确认删除?进回收站」变宽致 flex-wrap 换行,审计 #4】
2. **落点错开或 300ms disabled,二选一**:执行钮不得出现在触发钮的原落点上(执行放左、取消放右),**或**执行钮出现后 300ms 内 disabled 防连击——这是审计 P0 #5 修法的原文,桌面走前者(159 起清空回收站两处共用 `src/trash-purge.ts`:原钮置灰 + 下方另起确认区 + 全宽执行钮;删标签执行左、取消右;合并的确认进提示行、原钮置灰;移空间面板 `move-space.ts` 的「选目标」与「确认移动」分两行,连点两下目标只是选中);「管理列」的删列确认 158 起为与卡片删除确认同序(取消在前、红实心执行钮在后)改走后者(`column-manager.ts` 的 `CONFIRM_ARM_MS`,不置 disabled、只是 300ms 内不接)。⚠ 本条曾被抄成「并叠加」,在 §2.4 挂账约五周;2026-08-08 用户拍板「或」是原意,改回并销账(过程见 progress-log 340 §四、344 续)。【违例:清空回收站执行钮与原按钮右缘对齐,双击即全清,审计 #5】
3. **Esc 逃生**:确认态复用 armDismiss,Esc / 点外即取消——全应用交互中唯独确认流没有逃生键是不可接受的。(审计 #12)
4. **自动复原**(安卓 `CONFIRM_REVERT` 6s,见 §2.4;到点先过 `BAR_RETIRE` 余温再收)+ token 防重放。(审计 #4)
5. **周边无雷**:确认态出现时,毗邻控件不得是单拍即写的(状态 pill、恢复钮等)。(审计 #4)
6. **权重升格**:数据后果越重,确认钮越大——空间重置这类删全部数据的确认按钮应全宽、与取消拉开距离。(审计 #11)
7. **焦点停【取消】**(W5 Q3):确认一出来焦点一律落在【取消】上 —— 回车不做破坏的事,要做就 `Tab` 一下到执行钮;「彻底删除」这类焦点原先根本不进的,也让它进来停【取消】。

### 3.3 提交型输入(所有 Enter 提交点)

- 第一行永远是 `if (e.isComposing) return`——中文 IME 组合期的 Enter 是选词,不是提交。适用:捕获浮窗、灵感「记下」、看板新建、行内编辑、topics 表单、安卓 compose。【违例:全仓无一处 isComposing,审计 #1】
- 每个提交点配 in-flight 闸(照抄 openEdit 的 `saving` 模式):提交中忽略再次触发,防 IPC 往返窗口内双 Enter 重复入库。【违例:main.ts 捕获 / inbox.ts save / board.ts submitNewTask,审计 #2】
- 成功后的反馈契约:清空输入框;**安卓额外 blur 收键盘** + 新卡 `.flash` 高亮入场(连记场景给「继续记」显式入口,而不是永不收键盘)。【违例:save() finally 无条件 ta.focus(),审计 #7】

### 3.4 错误呈现分级

- **卡片级失败**(单卡的 archive/seal/标签/恢复失败):就地显示在该卡上(inbox 编辑态已是此模式,推广之),其余内容不动。
- **整版错误页**(renderError):只保留给列表**初次读取**失败,且必须带「重试」按钮。
- 禁止:小操作失败把整个看板/列表连 compose 一起替换掉。【违例:board.ts call() / tasktime.ts / inbox.ts doArchive 等全走 renderError,审计 #6】
- 任何写操作失败必须有可见反馈——删图失败无反应、取图列表失败显示为「无图」这类静默失败不允许。(审计 #26)
- **此刻做不了的入口事前淡着、说原因,⛔ 别等用户填完再报错**(看板优化那轮):淡着(`.blocked` + `aria-disabled`)但照列、照可点,title 写原因,点它或按它的快捷键只弹原因、不调命令;真执行仍由 core 现场校验。例:看板放不进新卡(落点 ⊥)时的「+ 新建卡片」/ 手机 ＋ / 随记「转待办」(桌面菜单项走 `hotkey-menu.ts` 的 `Act.blocked`)。

### 3.5 焦点与键盘

- **键盘焦点一个样子**(W5 A18,`theme.css`):`:focus-visible` 一律 2px `--ink` 实线、离控件 2px;文本框(各自写了 `outline:none`)画在 box-shadow 上、用 `--ink-soft`(引擎对文本框恒判 focus-visible,记一笔框开机就拿焦点,实墨那圈太重;捕获浮窗那只框不画);键盘焦点在卡的 ⋯ 上时整张卡也描这一圈,和鼠标悬停分开。⛔ 别用朱砂 —— 那是「选中 / 落点」的颜色。
- **桌面卡片「选中 = 焦点」三条**(W5 A2 / A3 / A7,`hotkey-menu.ts`):焦点进了一张卡就选中这张;`↑` `↓`(看板还有 `←` `→` 换列)挪选中时焦点跟着挪到新那张的 ⋯;键盘焦点在卡里时鼠标路过别的卡不抢选中。单键离场(删 / 转 / 挪列 / 归档 / 还原)后选中与焦点落到原位后一张,原地不动的(换色、列首列尾)留在那张;整列重画按条目 id 接回同一张。
- 所有 hover 显形的控件必须同时 `:focus-visible` 显形(补 `opacity:1; outline`),容器配 `:focus-within`。【违例:标签行操作、.dtask-copy 键盘焦点不可见,审计 #20;`.hk-btn` 157 起已有 `:focus-visible` 描边(W2 走查 N-10 实测),从违例里摘掉】
- **hover 显形的容器一旦就地展开「要交互的东西」(输入框 / 调色板 / 两拍确认 / 失败提示),必须钉住可见、不再依赖悬停。** 否则鼠标一离开那一行它整块隐形,而键盘焦点还在输入框里(看不见的输入框);报错更是当场变成**静默失败**,与 §3.4 末条直接打架。判据 = 进入非默认态时加一个显式状态类,**且那一档不许淡入**(淡入期间 opacity 真的有一瞬等于 0——这同时是 e2e `waitForDisplayed` 判不可见的判据)。【377 修:标签行 `.topic-actions`;同形别处未扫,见 progress-log 377 可优化项】
- 模态面板(同步面板等):`role="dialog"`、打开即聚焦首个控件、Tab 圈闭在面板内不走到遮罩后。(审计 #21)【158 起看板「管理列」面板是第一处做全的(`column-manager.ts`:role=dialog / 打开聚焦首个控件 / Tab 圈闭 / 关闭钮);159 起移空间面板(`move-space.ts`)同形:打开即滚进视口、聚焦第一个目标、Tab 圈闭、Esc / 点外退出。W5 起放大编辑 `.ze-panel` Tab 圈住、看板留言浮层 `.cm-panel` 键盘接管做全(焦点进、Esc 关、焦点还回)⛔ 别只给新面板单独发明一套】**878 起关窗那一问的模态抽成 `confirm-dialog.ts`,混版提醒共用;⛔ 别再另造一只确认模态(手机侧对应的是 `confirmBar` 的 `sticky` 形)。****161 / W4 A3 起设置浮层、同步浮层、关窗那一问共用 `dom.ts::holdKeyboard`**(打开即焦点进面板 / Tab 圈闭 / 浮层内按键不冒到 document,缩放键 `Ctrl` `+` `-` `0` 除外 / 关掉焦点还给打开它的那枚);同步面板整体重画时焦点按可见文字落回同一枚。**W5 Q2 起推到全应用的层与菜单**:卡片 ⋯ 菜单(焦点进第一项,`↑` `↓` Home End 走项、`→` 进「移到 ▸」、`←` 退回)、`/` 菜单、空间菜单、看板留言浮层、随记卡里展开的历史 / 留言(样子不动)、标签合并模式、各确认块、截止 / 优先级 / 颜色那几排、看板新建框 —— 打开焦点就进、Esc 一律关、关完焦点还给打开它的那枚、选中留着。

- **筛选变了回那一串顶上,清掉回原处**(159 / W3 A5):加一层、换标签、改过滤词而仍筛着时,桌面落到筛出来那一串的最上面(否则停在尾巴、最新几条在屏外);清掉筛选回原阅读位(157 P11)两条不冲突。手机清掉选着的标签那一下,标签条滚回开头让「所有」露出来。每个空间各记自己的筛选与随记页阅读位(Q6,只在内存);桌面搜索页按「空间 + 词」记结果滚动位,回来还原(A17)。
- **定制滚动条要把四个部件一起定**(249):只要有任一 `::-webkit-scrollbar*` 规则命中,整条滚动条改走自绘,**没写到的部件退回浏览器默认的白**——轨道白一层(被 thumb 的纸边遮掉大半、平时看不出),横竖同现时右下角那枚 `-corner` 就露成一块白方块。定 `width` 就顺手定 `height`(否则横条比竖条粗一圈)、定 `-thumb` 就顺手定 `-track` / `-corner`(铺 `transparent` 让元素底色透上来,深浅色都自洽)。
- **卡片里的 `nowrap` 元素必须能缩**(249;900 补两处先例:筛选 pill 的名字包 `.flabel`、管理看板的角色 pill `.bcm-pill`):标签 chip / 日期 chip 这类 `white-space:nowrap` 的东西,一枚长内容就能把卡片撑破、逼出意外的横向滚动条(纵向 `overflow-y:auto` 会把横向一并从 `visible` 提成 `auto`)。做法=文字包一层做 `text-overflow:ellipsis`,操作按钮 `flex:none` 不缩(窄卡上先消失的不该是操作)。**别用 `max-width:100%` 封顶**:若包含块自己是 shrink-to-fit(inline-flex 的 slot 层),百分比循环引用会被浏览器直接忽略——要靠**每一层** flex item 都 `min-width:0`。
- **一行按钮挤不下时,让整枚换行,别让钮在自己内部折字**(510):窄列里的行内选择器(优先级 P0/P1/P2/清除〔903 起三档读作高 / 中 / 低,两端同〕、截止那枚日期钮+清除)是 flex item,默认会被压到 min-content —— 于是「清除」在屏上读作「清 / 除」,而 P0/P1/P2 压到 min-content 就**顶住不动、整行撑破卡片**、列体长出横滚条(实测卡宽 161 时溢出 5px、98 时 68px)。正解 = **给那一行 `flex-wrap: wrap`**,一条声明同时治掉两个患。⛔ **别改成给按钮加 `white-space: nowrap`**,两条理由都被实测钉过:①有 wrap 之后它**变不红**(flex 先断行再谈收缩,钮到不了「缩到要折字」那一步)= 不可达的防护 = 死码;②那个类往往是**共用**的(`.choice` 同时给标签选择器用,那边的字是用户自己起的标签名、可以任意长),nowrap 会让长名字当场撑破卡片。**验收要量**(`getBoundingClientRect` + `scrollWidth == clientWidth`),且**至少量两档宽度** —— 只在最宽那一档量,恰好是唯一不折的那一档(510 的立账读数就这么错了一次)。验收得**量**(`getBoundingClientRect` 逐层 + `scrollWidth == clientWidth`),光看截图分不清"缩了"还是"恰好没溢出"。(2026-07-29 看板长标签案;灵感 `.tag-label` / 搜索 `.chip` 是同一手法的既有先例)
- **长内容折叠(704,桌面看板长卡)**:上限走 `em` 不走 px(桌面界面字号 70%–200%、每档 10%,是整窗缩放,px 在放大档下把可见行数一路压掉;⚠ 手机端反过来 —— 那端字号走 WebView 原生 textZoom,`em` **不跟着走**,639 在 M12 上四档实测,要用 `lh`)。**先一律夹住、落 DOM 后量一次**:没真夹到东西的当场摘掉夹子(与没有这功能时逐字同形、也不长钮),量与写各一趟(别逐张「量一下改一下」= 每张一次强制重排),且**必须排在「还原滚动位」之前**(上一条还的是夹后几何)。**豁免条款要按它自己写下的理由去量**:704 第一版写「正文里有没勾的方框就不折」,而理由只有「褶子下面的框点不到」⇒ 框全在夹线以上的卡被白白放行(整列占满),改成量方框底边有没有越过夹线才对;⛔ 别用「含不含某种东西」这类文本代理当判据。展开态**只活一次挂载**,不进库 / localStorage / 同步(「读一眼」的手势不是模式)。实现与八例 e2e:`src/board.ts::settleFolds` / `e2e/specs/board-card-fold.e2e.js`。**159 起回收站、搜索结果、标签页展开也折八行**(桌面 `fold.ts::settlePreviewFolds`,不记展开态;清单画成只读方框、长文不露 `#`);豁免「褶子下面有没勾的框」**只数点得动的框**(回收站里的框只读,数进去就永远不折)。
- **判定窗口不是白等,得立刻起过渡**(246):为等双击/长按判定而**故意挂起**的动作(看大图轻点关就是),挂起那段必须**在按下的那一帧就开始可见的过渡**(淡出/位移),第二击到了再把过渡平滑撤销。用户读成「卡」的是**点了没反应**,不是「没立刻完成」——所以别去砍判定窗口换手感,那是拿双击容错换的:安卓真机实测,窗口砍到 200ms 后间隔 226ms 的双击第一击就把图关了(系统标准 300ms/Android、500ms/Windows,砍到标准以下必出这种失手)。**验收要点**:光断言 class 挂上了不够,得量中途 `getComputedStyle().opacity` 落在 (0,1) —— 否则选择器写错、过渡根本没跑,断言照样绿。(2026-07-29 看大图关闭案:桌面 `.img-lightbox.closing` 只淡内容[黑底要留着盖住关闭那一下 —— 606 起那一下是**把遮罩窗藏起来**;605 是退出全屏、再往前是缩主窗]、安卓 `#viewer.closing` 整层淡)

- **编辑到一半离开 = 保存**(157 / P1,两端同规矩):点别处 / 返回都存;只有 Esc / 「取消」才丢,改过的话丢前问一句。桌面编辑态框下常驻一行「回车或点别处保存 · Esc 不要了」(902 用户拍板,知情推翻「不常驻说明书」;红字提醒出来时让位)。
- **复制失败一律说「复制失败:{原因}」**(902,桌面 `clipboard.ts::copyFailed`):钮上 / 菜单行里闪短的「复制失败」时,屏底同时出全句。
- 开关类的钮写动作全称:自动备份是「开启自动备份 / 停用自动备份」,不叫「关闭」(902)。
- 按钮标注真实行为:捕获窗「Esc 退出」实为收窗保稿 → 改「收起(草稿保留)」;桌面「关闭」实为隐藏到托盘 → 首次给提示(161 / W4 A5 已做:第一次点自绘的 ✕ 窗内问一句 `tray-hint.ts`,不靠托盘气泡 —— 专注助手会吞;Alt+F4 / 任务栏关窗不问)。(审计 #24、#27)

### 4.3 确认与错误文案

- 确认文案必须说明**后果边界**:「删除标签?已有条目不受影响」——不说明边界用户就不敢用。(审计 #24)
- 错误文案人话前置:原始错误码(如 UserSwitching)可保留在后半句,前半句必须是人能懂的一句话。(审计 #22)桌面实现 = `src/err.ts`(724;认得出的几类换人话、认不出的加「出错:」),手机 = `android/src/err.ts`(725,匹配面照抄)。159 起标签 / 空间撞名的那句(「已有同名空间「…」」)原样显示在框下、不带「出错:」、字留在框里;挪空间被拒的原因(`moveOutcomeText`)直接显示、⛔ 别过 `errText` —— 过了会被认成「那一条已经不在了」(W3 A2)。
- placeholder 与实际能力一致:搜索覆盖任务/回收站/归档就别写「搜索灵感的内容」,无结果文案同理。(审计 #24)

### 4.4 时间写法(165 / W5 Q14,两端同句)

- 卡上、回收站、归档、长文、搜索结果里的时刻一个规矩:今天的写「今天 15:18」,今年别的天写「11月5日 15:18」,跨年带年(两端同键 `ui.whenToday` / `ui.whenThisYear` / `ui.whenOtherYear`;手机 `ui.ts::fmtWhen` 一处)。
- 两处例外照旧:随记时间轴上的卡只写时刻(组头已写了哪天);截止胶囊窄,用短写法(「11/4」「7 天后」「逾期 1 天」);章头是一枚遮罩画的线条日历(颜色 `currentColor`,两端同一段 CSS;此前的日历表情上恒印着一个日期,901 换掉)。

## 六、工程约定(不进设计系统,进 repo 的开发规范)

这些是审计 #9 一族的根因约定,设计系统管不到,但必须成文:

1. **状态归属**:编辑态、草稿、暂存图一律在模块态(state),禁止只活在 DOM 里——切视图/切空间/远端刷新都不应丢。(审计 #9d)
2. **监听回收**:每个 mount 文档级监听的视图必须提供 unmount 清理钩子;残留监听对旧 id 发 commit 是数据事故。(审计 #9a)
3. **刷新前保护**:**回窗 / 远端落地那类刷新(`refresh(true)` / `load(true)`)在编辑中一律延后**,编辑态收场那一发再取真相重画(716;此前是「先 commit 再重画」—— 别的设备同步来任何改动都会把正打着字的编辑框存成一版并关掉);用户自己发起的刷新(离场 / 挂标签 / 记下)照旧先 commit 再重绘。inbox 与 board 行为必须一致。(审计 #9b)
4. **指纹短路**:所有全量重绘入口配 lastSig,内容未变不重绘(topics 补齐)。(审计 #9c)
5. **竞态守卫在 await 之前**:菜单双开类守卫必须在异步调用前置位。(审计 #21)
6. **昂贵查询缓存**:list_item_images 之类按会话缓存,重渲不重查(审计 #19)。不可变数据(图字节:只增删不改)按 id 缓存**成功结果**、永不失效,删除时清项只是内存卫生;⚠️ 只缓存已到手的值,不缓存 Promise——统一 invoke 包装把跨空间迟到响应变成「永不决议」(space.ts stale),缓存 Promise 会把这种挂起永久钉进 Map。(2026-07-19,item-images.ts srcCache)
